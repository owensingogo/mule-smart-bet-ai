# Mule Smart Bet AI — Starter project

A mobile-first PWA with Firebase email/password authentication, personal ticket history, command-based ticket builder, fixture display through a private API proxy, and a probability-estimation baseline.

## Security first
The API-Football key pasted into chat should be regenerated before deployment. Put the replacement key only in `backend/.env`; never commit that file. Firebase's web config is client-side project identification; secure Firestore with the supplied rules and enable Firebase Auth.

## Firebase setup
1. Firebase Console → Authentication → Get started → Email/Password enable.
2. Firestore Database → create database.
3. Firestore → Rules → paste `firestore.rules` and Publish.
4. Firebase project settings → Web app config is already placed in `js/firebase.js`; verify values.

## Backend API proxy
1. Install Node.js 18+ on your computer/server.
2. Copy `backend/.env.example` to `backend/.env`; replace `API_FOOTBALL_KEY` with your newly rotated key.
3. Set `ALLOWED_ORIGIN` to the frontend's deployed origin (during local development, use the local server origin).
4. In the `backend` folder run: `npm install`, then `npm start`.
5. Deploy this backend to a hosting provider that supports Node (not GitHub Pages by itself). Use environment variables on the host; do not upload `.env`.
6. Open the app Settings and enter your backend URL, e.g. `https://your-service.example.com`.

## Run frontend locally
Serve this folder using a local HTTP server (not file:// because Firebase ES modules require a web origin). Acode preview/server or another local static server is suitable. For deployment, host static frontend on Firebase Hosting or another HTTPS static host.

## Current limitations
- The ticket model is a deliberately basic, transparent prior, not trained on live team stats. It must NOT be represented as high-confidence AI prediction. Odds are illustrative placeholders until odds endpoints/data plan are integrated and mapped.
- API-Football fixtures route is included. Provider plan restrictions, season/date support and request quotas may affect data.
- It does not create genuine bookmaker booking codes or place bets. Such codes must be generated by each bookmaker's official platform/integration.
- Backend endpoints for statistics and odds are scaffolding; richer data ingestion and feature calibration are next development steps.
- Use betting responsibly. Predictions are uncertain; 15 combined odds is high risk.
